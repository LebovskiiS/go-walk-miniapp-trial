# miniapp — кабинет ситтера (Telegram Mini App)

Эпик KAN-490: проба (KAN-491/492) принята, кабинет достраивается по экранам. Без
сборки, без npm, без сторонних библиотек — `index.html` + JS-модули + CSS отдаются
как есть.

| Файл | Что |
|---|---|
| `index.html` | оболочка, CSP метатегом, SDK Telegram |
| `config.js` | адрес API и зона времени сервиса |
| `api.js` | вход по `initData` → JWT в памяти вкладки, повтор при 401, разбор конверта ошибок |
| `core.js` | общее: состояние оболочки, `esc()` и форматтеры, `fetchPage()`, реестр экранов, профиль и гейт, `render()`, события, `boot()` |
| `app.js` | точка входа: импорт экранов (порядок импорта = порядок вкладок) и `boot()` |
| `screens/schedule.js` | «Расписание»: два расписания одним редактором — выгул (`availability`) и заезды на передержку (`boarding_availability`, KAN-510), у каждого свой черновик; пауза, отпуск и выключатель общие |
| `screens/orders.js` | «Заказы»: три списка и карточка заказа (только просмотр) |
| `screens/offers.js` | «Новые»: предложения — принять/отказаться, отклик на экспресс, сообщение клиенту (KAN-506) |
| `screens/cabinet.js` | «Кабинет»: сводка (рейтинг, отказы, счётчики, трекер), история прогулок, отзывы — только чтение; `addCabinetLink()` — строки «Ещё» для разделов без своей вкладки |
| `app.css` | стили на переменных темы Telegram (светлая/тёмная) |

## Как добавить экран

1. Файл `screens/<экран>.js`. Состояние экрана — переменные модуля, не общий `state`.
2. В нём `registerScreen({ key, label, view, open, actions, changes })` из `core.js`:
   `view()` возвращает строку HTML, `open()` зовётся при переходе на вкладку,
   `actions` — обработчики `data-act` (получают `dataset`; вернул `Promise` —
   перерисовывает сам, иначе `render()` вызовет ядро), `changes` — обработчики
   `data-change` (получают `input`).
3. Одна строка импорта в `app.js`.
4. Стили — своим блоком в конец `app.css`.

Экран поверх вкладок (карточка заказа) — `registerOverlay({ isOpen, view, close })`:
ядро само покажет кнопку «Назад» Telegram. Состояние, зависящее от профиля, экран
пересобирает в `onProfile(hook)` — хук зовётся на каждом `applyProfile`.

Всё, что пришло с сервера, в HTML попадает только через `esc()`.

## Как это живёт

- Статика раздаётся с GitHub Pages из отдельного публичного репозитория
  `LebovskiiS/go-walk-miniapp-trial` — содержимое этой папки (вместе с `screens/`)
  копируется туда. CI/CD, Caddy и манифесты проекта не участвуют.
- Открывается по прямой ссылке бота ситтеров (`/newapp` в @BotFather). В самом боте
  при этом ничего не меняется.
- В ядре — `POST /auth/telegram/webapp` и CORS-список (KAN-491, раздел DEPLOY.md
  «Включить вход из Telegram Mini App»).

## Границы

Бэкенд под экраны не меняется: не хватает ручки — отдельный тикет. Секретов в
статике нет.
